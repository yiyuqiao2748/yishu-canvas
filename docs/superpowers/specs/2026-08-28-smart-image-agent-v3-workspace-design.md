# Smart Image Agent v3 工作区设计

## 目标

将 Smart Canvas 的图片 Agent 改为画布优先的紧凑工作区。用户在画布中完成“输入需求 → 查看方案 → 确认生成 → 使用结果”，而不是在难读的右侧长面板中寻找控件。

## 已确认事实

- v3 的生成、方案确认、执行队列、引用和结果均已由现有 API 与状态机实现。
- 当前 `shell.js` 把全部区域固定放进右侧栏；CSS 会压缩 `.shell` 的可用宽度。
- 助手模型与生图模型已通过独立的 provider/model 路由配置；当前图片 Agent 界面只选择生图模型。
- OAIREGBOX 的可见模型应由服务端用 `GET /v1/models` 发现；该网关没有可用于画布的通用文件上传或通用参数 Schema。

## 范围

- 仅调整 Smart Image Agent v3 工作区的 DOM、CSS、可访问性文案与无付费请求的测试。
- 保持已有 API、方案确认门、计费显示、引用上限、并发执行和结果动作。
- 保持助手模型配置为服务端 Provider 设置；不在本轮向画布暴露密钥或新增模型切换控件。

## 采用方案：底部创作坞站

1. **画布全宽**：v3 打开时不再缩窄 `.shell`。Agent 容器固定在画布底部、居中，宽度受限于桌面视口。
2. **紧凑顶栏**：只保留“图片 Agent”、引用数量和画布视图操作；引用区默认折叠，按需展开。
3. **单一创作入口**：底部输入框始终可见；比例、图片模型、数量与主按钮同行，控件都有显式标签或可访问名称。
4. **状态按需展开**：无任务时显示创作坞站；有待确认方案时展开方案卡；执行中显示事件与状态；完成后显示横向结果带。结果仍会插入原画布。
5. **可读性底线**：不使用逐字换行的图标尺寸按钮；正文与可操作文字不低于 12px；窄视口时坞站改为全宽堆叠，不遮挡主操作。

## 方案取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 修补右侧栏 | 改动最小 | 仍挤压画布，与目标参考不一致 | 不采用 |
| 底部创作坞站 | 画布优先、工作流连续、复用现有状态机 | 需要重排 v3 容器与响应式样式 | 采用 |
| 全新节点编辑器 | 自由度高 | 改动执行与数据模型，风险过大 | 不采用 |

## 助手模型后续接入边界

未来在 Provider 设置中增加“图片 Agent 助手”选择器即可；其可选项只能来自服务端按令牌读取的 `/v1/models`，保存 provider ID 与 model ID，不保存或下发 API Key。该设置只影响方案规划，不能改变用户选择的图片模型。

## 验收标准

- 桌面端打开图片 Agent 时画布不再因右栏被压缩。
- 新需求、比例、模型、数量、生成按钮在同一可读创作坞站中。
- 引用、方案、执行详情、结果只在需要时展开，且保留原数据属性与行为。
- 空需求、待确认方案和结果继续操作的回归测试通过。
- 不调用 OAIREGBOX 的付费生成接口；不改 Supabase 迁移或远程环境。
