# Smart Image Agent v3 可用性修复设计

## 目标

将 Smart Canvas 的 v3 右侧创作面板修复为在桌面端可读、可操作的界面；修复空需求点击后静默无反馈的问题。保留现有生成、计费、Supabase 和 Provider 调用路径。

## 已确认事实

- v3 `shell.js` 输出中文文字画布控制按钮，但 `smart-image-agent.css` 将其设为 28px 图标按钮，导致文字逐字换行。
- v3 `shell.js` 使用 `sia-section-head`、`sia-reference-actions`、`sia-composer-controls` 等类名，而样式表主要定义的是另一套旧类名，导致布局规则未生效。
- `v3/app.js` 在需求文本为空时直接返回，不显示任何提示；截图中的上方灰色文本是已完成方案，不是底部“生成方案”的新需求输入。
- 侧栏、v3 静态脚本与本地 FastAPI 服务均可访问；本轮不需要 Provider 图片生成验证。

## 方案比较

1. 仅把文字按钮改为图标：可消除竖排，但方案区和输入区仍难以区分，空输入仍无提示。
2. 让样式表与 v3 DOM 契约对齐，并补齐必要反馈：推荐。改动局限在 v3 UI，保留所有业务接口与状态机。
3. 替换为全新多页工作流：视觉自由度最高，但会扩大范围并影响已验证的执行路径。

## 采用设计

- 侧栏桌面宽度使用可读下限；标题、状态、表单和按钮使用不低于 12px 的正文尺寸。
- 画布操作保留为紧凑按钮，但以单字中文标签和 `title` 辅助说明呈现；不允许逐字换行。
- 为 v3 实际使用的类名补充样式：引用区、方案卡、活动区、结果区、输入区、模型/比例/数量控件。
- 已完成方案以“当前方案”标签与禁用态展示；底部新需求输入区使用明确标签和可见边界。
- 空输入点击显示明确错误提示，焦点回到输入框；已有待确认方案时保留现有阻止逻辑和提示。
- 新增无浏览器依赖的源代码契约测试，覆盖空输入提示、v3 DOM/CSS 关键选择器和控件可读性约束。

## 不在范围内

- 不改 Provider 请求、模型计费、数据库结构或 v3 执行状态机。
- 不执行新的真实 Provider 图片生成。
- 不进行全站视觉重构。

## 验收

- v3 面板的控件不再出现逐字竖排，底部输入区与当前方案可区分。
- 空输入点击显示“请先输入创作需求”并聚焦输入框。
- 现有 v3 回归测试、针对性 UI 契约测试、静态构建和 `git diff --check` 均通过。
